# Agent runbook: Nemotron 3.5 Lightning GGUF

Run from this directory on the user's DGX Spark. Complete the installation only when `./start.sh health` succeeds and `/v1/models` lists `SERVED_MODEL_NAME`. Do not use a private dispatcher, another recipe, or an existing site-specific model tree.

1. Read [.env](.env) and [README.md](README.md#the-included-env). Defaults are complete; no copy step. Inspect `uname -m`, `nvidia-smi -L`, `free -h`, `df -h`, `python3 --version`, and available ports (`ss -ltn`). Plan for at least 43 GiB free for the GGUF and 3 GiB for the engine, plus at least 48 GiB available RAM. Choose a free `PORT` and sufficient cache filesystem. Never stop an unrelated service to take its port.
2. If weights are preloaded, set `MODEL_PATH` to the file or its directory and `AUTO_DOWNLOAD=0`; a complete Hugging Face cache can keep `MODEL_PATH=auto` with `AUTO_DOWNLOAD=0`. For a preinstalled compatible server, set `LLAMA_SERVER` to its executable. Keep any `HF_TOKEN` in the shell environment. Review the dry run with `./start.sh --dry-run`; check the model repo and filename, engine URLs, full llama-server command, paths, bind address, and port. Dry run must have no side effects.
3. Run `./start.sh`. It checks architecture, GPU, RAM, port and disk; downloads or checks the GGUF; verifies engine archive SHA-256; checks binary flags; starts llama-server; and polls `/health` and `/v1/models` up to `STARTUP_TIMEOUT`. An interrupted download can be retried. On failure inspect `./start.sh logs`, storage, RAM, and binary compatibility before changing settings. Do not start a second instance while the first is loading.
4. Run `./start.sh health`, `./start.sh status`, and `curl -fsS http://127.0.0.1:8003/v1/models` (substitute configured host/port). Report HTTP health, model ID, endpoint, model and engine paths, and any departure from defaults. If `HOST=0.0.0.0`, use `127.0.0.1` for local checks. A small inference request can confirm generation after health passes.

If `.env` changes after launch, review `./start.sh stop --dry-run`, run `./start.sh stop`, then `./start.sh`. The stop command checks the recorded process and leaves weights and engine files intact. If a stale PID file prevents startup, inspect the PID and `/proc/<PID>/cmdline` before removing that recipe-owned file. Never kill a process that the script does not identify as its own.
